# Tooling inventory

Last verified: 2026-07-29

This is the maintained development-tool inventory for BigBlue and
MotokoKusanagi. It records the tools a researcher is expected to invoke
directly. It is not an exhaustive dump of Homebrew's transitive libraries:
those can change during routine maintenance and are not part of the workstation
contract.

Both machines pass:

```sh
./scripts/bootstrap-dev-environment.sh
./scripts/verify-dev-environment.sh
```

Different global versions are expected because the Macs run different macOS
and Apple SDK releases. Project runtime declarations and lockfiles, rather than
globally identical package-manager state, provide reproducibility.

| Tool | Utility | BigBlue | MotokoKusanagi |
| --- | --- | --- | --- |
| Tailscale | Private encrypted network between the Macs without router port forwarding | Installed and operational | Installed and operational |
| OpenSSH | Interactive remote shells and the transport used by Git and `rsync` | 9.0p1 | 9.7p1 |
| `rsync` | Deliberate resumable file transfer over SSH | 2.6.9 | 2.6.9 |
| Git | Distributed source history and the local half of the GitHub workflow | 2.39.2, Apple Git | 2.39.1, Homebrew |
| GitHub CLI (`gh`) | Repository and GitHub operations from the terminal | 2.83.1 | 2.45.0 |

Tailscale and SSH have been tested in both directions. GitHub push and pull have
also been tested from both machines. GitHub is authoritative for committed
source; `rsync` is for deliberate data transfer, not live repository syncing.

| Homebrew | Shared macOS command-line package manager | 6.0.13 | 6.0.3 |

| Ninja | Fast low-level build runner commonly generated by CMake | 1.13.2 | 1.13.2 |
| `pkg-config` | Locates installed native libraries and compiler flags | 3.0.4 | 2.3.0 |
| `jq` | Queries and transforms JSON in scripts and data pipelines | 1.8.2 | 1.8.2 |

The shared `Brewfile` declares only lightweight tools used across projects:
CMake, Fish, GitHub CLI, `jq`, Ninja, and `pkgconf`. It does not request a
blanket package upgrade.

BigBlue runs macOS Ventura, a Homebrew Tier 3 host. Native bottles may be
unavailable there, so heavyweight current formulas can unexpectedly compile
from source. `uv`, R, and optional linting tools are deliberately handled
outside the shared Brewfile.

## Language environments

| Tool | Utility | BigBlue | MotokoKusanagi |
| --- | --- | --- | --- |
| Python | General scientific programming interpreter available to the workstation | 3.14.6 | 3.13.1 |
| `uv` | Installs project Python versions, resolves dependencies, creates `.venv`, and enforces `uv.lock` | 0.11.32, standalone | 0.11.23, Homebrew |
| `rustup` | Installs and selects Rust toolchains | 1.28.2 | 1.27.1 |
| `rustc` | Rust compiler | 1.89.0 | 1.83.0 |
| Cargo | Rust build and dependency manager | 1.89.0 | 1.83.0 |
| R | Statistical computing interpreter | 4.1.0 | 4.4.2 |

The global Python and Rust versions are discovery defaults, not project pins:

- Python projects use `pyproject.toml`, `.python-version`, and `uv.lock`.
- Rust projects use `Cargo.toml`, `Cargo.lock`, and `rust-toolchain.toml`.
- R projects use `renv.lock` and record the tested R major/minor release.

The R interpreter mismatch is known. It does not affect Python or Rust work.
Before running an active R project on both Macs, BigBlue should receive CRAN's
signed R 4.4.2 arm64 package, which is compatible with Ventura. Current R must
not be built through Homebrew on BigBlue.

| Tool | Utility | BigBlue | MotokoKusanagi |
| --- | --- | --- | --- |
| `latexmk` | Repeatedly invokes LaTeX as needed to build a complete document | 4.70b | 4.79 |
| TeX Live | LaTeX engine and package distribution | 2021 generation | 2023 generation |
| Overleaf | Hosted collaborative LaTeX editing and independent build path | Account workflow | Account workflow |

Manuscript repositories should state their build command and required LaTeX
packages. The two TeX installations are intentionally not upgraded as part of
the generic baseline because manuscript compatibility should be tested before
a distribution change.

## Available but not baseline-managed

- VS Code is present on both machines and is the main graphical code editor.
- Zotero and Obsidian are part of the research workflow, but their library
  organization and synchronization are separate projects.
- Docker is optional and currently not required by the baseline. Add it only
  for projects whose services or system dependencies justify containers.
- `shellcheck`, `ripgrep`, Quarto, Node.js, and container runtimes are not
  required shared tools. A project may add them when needed.
- BigBlue still contains a legacy Intel Homebrew under `/usr/local`; scripts
  explicitly prefer the native Apple-silicon installation under
  `/opt/homebrew`.

## Updating this inventory

Run on each Mac:

```sh
./scripts/audit-dev-environment.sh
./scripts/verify-dev-environment.sh
```

Update this document when a baseline tool is added, deliberately removed, or
changes role. Ordinary patch-version drift does not require immediate
harmonization, but the inventory should be refreshed after planned workstation
maintenance or a macOS upgrade.
